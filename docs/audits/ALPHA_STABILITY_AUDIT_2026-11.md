## 1. Executive summary

В изолированном JavaScript-стенде с реальным текстом `tutorial.js + game.js`, фиксированным PRNG и без DOM завершено **300/300 обычных партий** (100 за каждую фракцию) и **100/100 детерминированных учебных партий**. В 300 обычных партиях: 0 исключений, 0 незавершённых, 0 обнаруженных нарушений контролируемых инвариантов, 0 расхождений независимого финального подсчёта; ничьих — 10. Дополнительно выполнены 18 адресных проверок механики. Это фактические прогоны в JS V8, **не запуск файлов Node.js из checkout и не браузерное E2E**.

Обнаружен **один воспроизводимый MAJOR-дефект** PWA: при HTTP 503/404 для навигации service worker сохраняет ошибочный ответ в кэш под `./index.html`. Это способно нарушить последующий офлайн-запуск. Отмечены три явно устаревших тестовых скрипта и устаревшие описания документации (MINOR). Основной игровой цикл выглядит устойчивым по проверенному объёму, однако Safari, тач-жесты и реальное обновление установленной PWA не проверены. Полную корректность всех цепочек способностей и визуальное качество объявлять подтверждёнными нельзя.

## 4. Проверка игрового движка и карточной логики

**A1/A2.** Статически прослежены `newGame → startTurn → aiPlan/place → endTurn → раскрытие → endTurn abilities → finish`. В обычных симуляциях видны корректные шесть ходов, 3 стартовые карты + добор на первом ходу, открытие локаций 1–3 и бюджет `turn - spent`. Обработчик пользовательской выкладки проверяет `canPlay` и `effCost` до `place`; `unplace` возвращает `paid`, скидку и надбавку. Асинхронное `endTurn` сохраняет `session=G` и сверяет его после задержек; `finish` сверяет `finishedSession`, `resultViewVersion`, фазу и режим перед показом результата через 700 мс. При повторном нажатии `endTurn` не проходит начальный guard вне `plan`.

**A3.** Проверено наличие 36 определений и сопоставлены для каждой карты ID, базовые cost/power, флаги артефакта и героя. В коде присутствуют функции и ветви разрешения следующих эффектов: инженерные баффы / ongoing / endTurn, астромантские draw, discount, surcharge, block, disable rule, улучшение карт по локациям, выбор из колоды/сброс руки противника, перемещение Сверхновой, хранительские дебаффы, копирование, trap, destroy и контроль ongoing. Фактическая проверка всех 36 эффектов по отдельности **не проведена**: 300 игр не гарантируют срабатывание каждой комбинации. По точным характеристикам расхождений с `docs/gifted-cards.md` нет.

**A4.** Текст всех девяти `LOCS` совпал с правилами в документации. Адресные сценарии прошли; вероятностный Колодец проверен только с принудительно удачным исходом, статистика 50% и поведение при неудаче не тестировались.

**A5.** `endTurn` подсчитывает по открытым картам число лидирующих локаций, выбирает сторону с преимуществом, при равенстве начинает игрок `p`; затем сортирует раскрываемые карты в пределах стороны по UID. Эффекты применяются после раскрытия каждой карты, включая капкан, правило локации и `onReveal`. Это подтверждено чтением кода; отдельная исчерпывающая таблица permutations порядка раскрытия/уничтожения не исполнялась. Изменять порядок без Architect запрещено.

**Неоднозначность для Architect (не записана как доказанный баг):** `canPlay(o,l)` не проверяет `G.locRev[l]`; обычная игра разрешает размещение карт на скрытых локациях уже в первом ходу, тогда как `Tutorial.beforePlace` требует открытую локацию, а перемещение Астромантки фильтрует только открытые. Неясно, планируется ли это как осознанная механика игры вслепую. Требуется решение Architect, **не менять код без спецификации**.

## 8. Mobile / PWA

**Статический PASS:** manifest JSON: `standalone`, относительные start/scope, PNG 192/512; `index.html` содержит iOS meta/viewport-fit=cover и ссылки на иконки; HTML использует CSS `tutorial-ring-fix1`, JS `approved-medallions-1`, что согласовано с APP_SHELL `v9`. Два бинарных WebP проверялись при предшествующей задаче, но в **этом аудите** на реальном iPhone не декодировались и не рендерились.

**Не подтверждено:** HTTP/MIME с GitHub Pages в текущем окружении; загрузка всех ресурсов APP_SHELL в реальном install; успешное обновление устаревшего SW; offline после перезапуска; поведения iOS Safari на разрешениях 375×812 / 390×844 / 393×852 / 430×932 и landscape; наложение статус-бара/индикатора домой; свайпы и drag-and-drop; touch target размер. Наличие CSS-правил safe areas **не заменяет** визуальную проверку.

**Риск обновления:** `service-worker.js` использует `cache.addAll(APP_SHELL)`; один неуспешный ресурс может отклонить установку нового SW. При навигации ошибка уже воспроизведена в F-01. Конкретный сбой установки на опубликованном Pages не подтверждён.
