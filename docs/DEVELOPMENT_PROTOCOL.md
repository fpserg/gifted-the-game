# GIFTED — Development Protocol

ChatGPT — продуктовый Architect; Claude Code — основной Builder; независимый Inspector — отдельный процесс, не участвовавший в реализации проверяемого изменения; Product Owner утверждает продуктовые решения и существенные релизы.

Порядок работы: docs/CLAUDE_WORKFLOW.md. Политика рисков, инспекции и публикации: docs/ORCHESTRATOR_POLICY.md. Обязательные ограничения: AGENTS.md. Все изменения через PR; Builder не выполняет merge. Architect фиксирует READY задачи и критерии, Builder запускает реальные тесты и открывает PR, Inspector проверяет точный HEAD и записывает вердикт, Architect или владелец публикует только по действующей политике. Не считать обсуждение или самооценку независимой инспекцией. Не менять правила, карты, экономику без утверждения; при утверждённых изменениях обновлять игровые документы. Проверять iPhone/PWA, safe areas, кэш и доступность; честно сообщать ограничения Safari. Отчёт: Task / PR / SHA / Scope / Tests PASS FAIL NOT RUN / Findings / Risk / Status.

Инспекция идёт по порядку Fail Fast (docs/ORCHESTRATOR_POLICY.md):
- сначала diff, архитектура и быстрые проверки;
- при воспроизведённом BLOCKER/MAJOR — сразу CHANGES REQUESTED с доказательствами, длительные проверки отмечаются NOT RUN/прервано;
- полные турниры и длительные измерения — только без блокирующих замечаний, с checkpoint, где он поддерживается;
- новый HEAD — новая инспекция;
- APPROVE — только после всех применимых обязательных и утверждённых проверок.

Обязательный CI не останавливается ради экономии.

## Handoff Protocol (Issue #54)
Game Design (GD) фиксирует утверждённые Product Owner продуктовые решения в Issue со статусом DESIGN APPROVED; только Architect определяет READY, очередь и технические критерии. Builders Guild (BG) — роль Builder (Claude Code).

После каждого действия по разработке BG, Inspector и GD завершают пользовательский отчёт (включая промежуточные, неуспешные и заблокированные действия) отдельным копируемым однострочным блоком: `BG <номер PR> done`, `Inspector <номер PR> done` или `GD <номер Issue> done`. Форматы до создания PR/Issue и порядок записи в GitHub — в docs/ORCHESTRATOR_POLICY.md, раздел «Передача управления Architect (Handoff Protocol)». Architect читает GitHub; Product Owner не копирует полные отчёты. Команда передаёт статус и не заменяет независимый вердикт, CI или разрешение на публикацию.
