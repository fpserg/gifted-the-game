## Изменения

Основа — исправления PR #30 (F-02–F-04). PR #30 не запускался через Node; при прямом запуске его версия `check-medallion-assets` падала. Эта ошибка исправлена здесь, поэтому настоящий PR заменяет #30.

- **check-medallion-assets** (из #30 + исправление): вместо прошитых версий читает фактические URL CSS/JS из `index.html` и `APP_SHELL`/`CACHE_NAME` из `service-worker.js` и требует их точного совпадения. Проверяет разметку обоих медальонов, fallback-подписи, пути WebP, CSS скрытия fallback и фон обучения. Исправлено: worker вычислялся дважды в одном контексте (`Identifier 'CACHE_NAME' has already been declared`). Бинарные проверки WebP и сетевой fallback service worker сохранены.
- **check-first-battle-ui** (из #30 + усиление): проверяет текущую разметку медальонов, события `load`/`error` и независимость fallback двух кнопок. Полная шестиходовая учебная партия, отмена, финал, повтор, выход и обычная партия сохранены. Возвращена проверка `G === null` после выхода во время раскрытия; проверка из #30 о том, что старый таймер не меняет новую партию, тоже оставлена.
- **check-normal-regression** (переписан): 90 партий ИИ против ИИ с фиксированными seed (3 фракции × 30) сравниваются с базовой версией из git (по умолчанию `origin/main`, затем `main`, затем `HEAD`) или с файлом `game.js`, переданным аргументом. Добавлены проверки обычного режима, завершения шести ходов и воспроизводимости seed. Мутационная проверка: изменение силы одной карты на +1 ловится.
- **simulate-balance** (из #30 + расширение): совместим с текущей сигнатурой, патч выбора соперника применяется только в памяти и проверяется точно. Добавлены доли в %, сводка по фракциям, `totalGames` и экспорт `simulate()` для тестов. Интерфейс CLI прежний.
- **check-simulate-balance** (новый): 3000 партий за прогон (1000 на пару, обе стороны) по реальному `game.js`. Проверяет согласованность счётчиков, SHA-256 исходного `game.js`, идентичность при одинаковом seed и отличие при другом seed.

Ни одна существенная проверка не удалена; изменения покрытия перечислены выше. Мутационные проверки: рассинхрон версий HTML/SW, удаление медальона из кэша, удаление fallback-подписи, отключение скрытия fallback, отсутствие обработчика `error` и изменение сигнатуры `newGame` — каждая приводит к FAIL.

## Результаты симуляции

`node scripts/simulate-balance.cjs game.js 10000 20261118` — 30 000 партий (10 000 на пару), seed 20261118, LCG32, `game.js` SHA-256 `20b742d2f782ae613aef08140177f3140b3ac6eff6bbec0c545f326db347e310`. Два прогона дали идентичный результат.

| Пара | Победы A | Победы B | Ничьи |
|---|---|---|---|
| Инженер — Астромантка | 49,88% | 48,15% | 1,97% |
| Инженер — Хранитель | 46,80% | 49,54% | 3,66% |
| Астромантка — Хранитель | 45,82% | 51,41% | 2,77% |

По фракциям (20 000 партий каждая): Инженер 48,34%, Астромантка 46,99%, Хранитель 50,48% побед.

**Ограничения:** обе стороны играют одинаковым жадным `aiPlan()`; он не планирует с учётом эффектов карт. Выбор целей Астромантки без DOM делается встроенной эвристикой движка. Это доли побед модели, а не людей; по ним баланс не корректировался и не должен корректироваться без отдельного решения.

