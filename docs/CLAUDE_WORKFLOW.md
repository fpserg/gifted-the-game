# Переход на Claude Code
После утверждения и включения данного PR Claude Code заменяет Builders Guild как основной исполнитель. ChatGPT остаётся продуктовым архитектором; Product Owner утверждает решения и публикацию. Независимый Inspector не является исполнителем проверяемого изменения. Действуют AGENTS.md, обновлённые DEVELOPMENT_PROTOCOL.md и ORCHESTRATOR_POLICY.md. Независимый вердикт фиксируется в PR на точный SHA; отдельный GitHub approval не требуется. Автоматизация merge не активируется; PR #32 не сливать в прежнем виде.
## Очередь
Architect создаёт Issue с явным статусом READY, приоритетом, продуктовым разрешением, scope, критериями приёмки, риском и зависимостями. Claude проверяет актуальный main и открытые PR, не дублирует работу. Приоритет P0 выше P1 выше P2; при равенстве старшая задача первая. При неоднозначности — BLOCKED. Отчёт и PR привязаны к Issue. После независимой проверки публикацию L0 разрешает Architect, L1/L2 и защищённую инфраструктуру — Product Owner; merge только по действующей политике без обхода защиты.
## Первичная настройка
Подключить Claude Code к репозиторию fpserg/gifted-the-game с минимально необходимыми правами на чтение, ветки и PR. Не выдавать административные права, не отключать защиту main. Проверить доступ чтением CLAUDE.md и списка задач. Не передавать токены в чат или git.
## Первые шаги
Проверить открытые PR #28, #30; #32 заморожен. Не сливать автоматически. Стабилизация тестов предшествует изменениям правил. Новые игровые изменения требуют отдельной READY задачи и утверждения Product Owner.
## Возврат после инспекции
При CHANGES REQUESTED Builder исправляет findings в том же PR и прогоняет затронутые проверки. Затем представляет новый HEAD для повторной независимой инспекции. Проверки, которые Inspector отметил как NOT RUN или «прервано», не считаются пройденными: они выполняются на новом HEAD по порядку Fail Fast из docs/ORCHESTRATOR_POLICY.md.

## Передача управления Architect (Issue #54)
Claude Code выполняет роль Builders Guild (BG). После каждого действия по разработке записывает фактический результат в Issue/PR и завершает пользовательское сообщение-отчёт отдельным копируемым блоком кода с одной строкой `BG <номер PR> done` (до создания PR — `BG issue <номер Issue> done`; без номера — `BG done` с указанием причины в отчёте). Это обязательно также для промежуточных, неуспешных и заблокированных действий. Если запись в GitHub невозможна, явно сообщить об этом. Команда передаёт управление Architect, не означает успех, READY, APPROVE или разрешение на merge. Полные правила для BG, Inspector и GD — в docs/ORCHESTRATOR_POLICY.md, раздел «Передача управления Architect (Handoff Protocol)». Все прежние требования к отчётам, проверкам и публикации сохраняются.
