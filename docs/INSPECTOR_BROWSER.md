# Независимый браузерный замер Inspector (GIFTED-INSPECTOR-CI, #51)

Утверждено PO 26.11.2026 (Issue #51). Инструмент для **независимого Inspector**. Inspector сам запускает замер и сам оценивает результат. Builder не выдаёт вердикт и не подменяет запуск Inspector своим тестом.

Это **не обязательный статус CI** и не часть `alpha-regression`. Защита веток и полномочия не меняются.

## Что измеряется
Методика #46 (та же, что `scripts/measure-tactician-browser.py`):
- время каждого решения стратегии (по умолчанию `strategist`) против Новичка;
- headless Chrome с замедлением CPU через CDP (`Emulation.setCPUThrottlingRate`), по умолчанию 1×, 4×, 6×;
- `games` партий на каждую скорость (по умолчанию 60): места p/e чередуются, герои по кругу eng/ast/kee, партия g использует LCG-seed g+11, по 6 решений за партию.

Для каждой скорости отдельно по сторонам p, e и вместе:
- число решений;
- среднее, p50, p95, p99, максимум (перцентиль — ближайший ранг, floor);
- число решений дольше 1 с.

Дополнительно:
- **оценка без паузы подсчёта:** каждое решение минус медиана калибровки паузы;
- **верхняя граница:** время целых сегментов хода, в которых было решение (движок + решение).

Это эмуляция на CPU раннера, а не измерение смартфона. Реальное устройство — задача 004D.

## Разделение проверяемого кода и измерителя
Замечание инспекции на `7ca69fd`: проверяемый код мог подделать журнал. Теперь доверие к результату не зависит от проверяемого кода.

1. **Только в странице.** Проверяемый код в Node читается только как текст и исполняется лишь в одной офлайн-странице Chrome.
2. **Доверенный bootstrap запускается в странице раньше проверяемого кода.**
   - Он сохраняет в замыкании нужное ему: часы (`Performance.prototype.now`), `Reflect.apply`, типизированные массивы.
   - Журнал (`Float64Array`/`Int32Array`), счётчики и расписание партии хранятся там же, недостижимо из глобальной области. Глобальные переменные проверяемого кода, например поддельный `__t`, ни на что не влияют.
3. **Каждое решение измеряет доверенная обёртка** функции `plan` стратегии в реестре. Сторона и ход берутся из доверенного расписания, а не из контекста проверяемого кода.
4. **Каждый вызов исходной `plan` подтверждается вне страницы.** Точка останова CDP на этой функции приостанавливает её, а измеритель проверяет, что вызывающий кадр — доверенная обёртка (`functionLocation`). Сама функция должна быть определена в скрипте проверяемого кода, а не быть встроенной или функцией bootstrap.
5. **Расписание проверяется по сегментам** каждой партии: подготовка и ходы 1–6. Число вызовов обёртки должно совпасть с числом подтверждённых пауз и с расписанием:
   - место p — по одному решению на ходах 1–6;
   - место e — на подготовке и после ходов 1–5.

   Итого 6 решений за партию, обе стороны поровну, номера ходов 1–6. Кроме того, время в странице не может превышать внешнее время сегмента в Node.
6. **Запуск неуспешен, если:**
   - стратегия вызвана мимо обёртки;
   - есть лишние или пропущенные решения;
   - `plan` вернула объект или Promise (асинхронная или отложенная работа);
   - была неожиданная пауза (`debugger`);
   - проверяемый код изменил встроенные функции: `performance`, `Performance.prototype.now`, `Date.now`, `Reflect.apply`, `Function.prototype.call/apply/bind`, таймеры, `Promise`, `Math` и др.;
   - появился дополнительный фрейм (`iframe` — новая область с чистыми встроенными функциями), worker, shared worker или страница/попап;
   - страница была перенаправлена или выбросила необработанное исключение.
7. **Пауза подсчёта входит во время решения.** Поэтому время не занижается. Её величина измеряется калибровкой на пустой доверенной функции для каждой скорости и публикуется.

## Системная изоляция (`--isolation=strict`, в workflow)
- **Сеть.** Измеритель вместе с Chrome запускается в отдельном сетевом пространстве имён (`unshare --net`), где есть только loopback. Измеритель сам проверяет, что:
  - в `/proc/self/net/dev` нет интерфейсов, кроме `lo`;
  - адреса `1.1.1.1:443`, `140.82.112.3:443` и `127.0.0.1:9` недостижимы.

  Связь с Chrome идёт через pipe (`--remote-debugging-pipe`), без TCP-порта. Дополнительно страница переводится в офлайн-режим, а имена хостов не разрешаются.
- **Песочница Chrome.** Пользователь без прав root, флага `--no-sandbox` нет. Отчёт самого Chrome (`chrome://sandbox`, отдельная доверенная страница измерителя) должен показывать «You are adequately sandboxed», PID- и сетевые пространства имён и Seccomp-BPF. Workflow включает непривилегированные user namespaces, которые на Ubuntu 24.04 ограничены AppArmor и нужны песочнице.
- **Среда.** `env -i`: разрешены только PATH, HOME, TMPDIR, LANG, LC_ALL, TZ и метки образа. Любая другая переменная, например `GITHUB_TOKEN`, — неуспех.
- **Файлы.** Каталоги измерителя и проверяемого кода принадлежат root и доступны только для чтения. Измеритель проверяет, что не может их изменить.
- **Workflow:**
  - `permissions: contents: read`;
  - секретов нет;
  - оба checkout с `persist-credentials: false`;
  - нет `pull_request_target`;
  - параметры попадают в shell только через `env` и строгие шаблоны (`set -f`).

## Запуск (Inspector)
Workflow `.github/workflows/inspector-browser.yml`. Он и измеритель всегда берутся из `main`.

1. **Комментарий в PR от владельца репозитория** (`author_association == OWNER`). Это доступно Inspector через инструменты комментирования:
   ```
   /inspector-browser sha=<40-символьный SHA> [strategy=strategist] [games=60] [rates=1,4,6]
   ```
   Workflow с событием `issue_comment` GitHub всегда запускает из ветки по умолчанию. Комментарии других пользователей и комментарии к Issue без PR задание пропускает.
2. **`workflow_dispatch`** — Actions → «Inspector browser measurement» → Run workflow, ветка `main`; или через CLI:
   ```
   gh workflow run inspector-browser.yml --ref main -f sha=<SHA> -f strategy=strategist -f games=60 -f rates=1,4,6
   ```
   Нужно право write, у владельца оно есть.

Оба способа работают только после появления файла в `main`.

Результат запуска:
- Summary;
- аннотации `::notice` с n/p50/p95/p99/max/>1 с для каждой скорости и стороны (видны при чтении запуска);
- артефакт `inspector-browser-<sha>-run<id>-<attempt>` на 90 дней: `measurement.json`, `raw-timings.json` (каждое решение и каждый сегмент с подтверждением), `summary.md`, при неуспехе `error.json`.

## Порядок шагов workflow
1. Разбор и проверка запроса: ветка запуска `main`, SHA — 40 hex, стратегия — идентификатор, числа — по шаблону.
2. Checkout измерителя (`github.sha` в `main`) и проверяемого коммита, оба без сохранения учётных данных.
3. Запись среды.
4. Подготовка барьера: user namespaces для песочницы; каталоги root-owned и только для чтения.
5. **Отрицательная проверка:** строгий запуск вне барьера должен отказать («network not isolated»).
6. **Самопроверка внутри барьера** — `check-inspector-browser.cjs --mode=isolated`, только доверенный код:
   - положительный запуск;
   - атаки (см. ниже);
   - грязная среда;
   - измеритель или проверяемый код, доступные на запись.
7. Замер внутри барьера.
8. Summary, аннотации, артефакт.

## Отрицательные сценарии (`check-inspector-browser.cjs`)
Каждый сценарий обязан завершиться ошибкой с ожидаемой причиной:
- **подделка журнала** при неисполненной стратегии — сценарий из инспекции: `__t` заполнен 12 строками, `aiPlan` пустая;
- пропущенное решение, лишнее решение;
- вызов стратегии в обход обёртки;
- `plan` — функция не из проверяемого кода;
- асинхронная `plan`;
- **подделка часов:** `performance.now`, `Performance.prototype.now`, `Date.now`;
- подделка `Reflect.apply` и `Function.prototype.call`;
- `debugger`;
- `iframe`, dedicated worker, shared worker, попап;
- **сеть:** страница должна быть офлайн, локальный HTTP-сервер не должен получить запросов (`fetch`, `Image`);
- неверный или сокращённый SHA, изменённый checkout;
- отсутствующий или не стартующий браузер;
- нет стратегии, ошибка страницы, превышение времени;
- в изолированном режиме — грязная среда, измеритель или проверяемый код, доступные на запись;
- в режиме `outside` — строгий запуск вне барьера.

## Ограничения
- **Пауза подсчёта** добавляет к каждому решению время калибровочной паузы: локально около 1–5 мс, при 6× до примерно 11 мс в максимуме. Публикуются и время с паузой, и оценка без неё.
- **Отложенная работа и предвычисление.** Работа, которую проверяемый код переносит из `plan` в движок или в отложенные задачи, не считается временем стратегии. Отложенный результат `plan` (Promise) обнаруживается, а сегменты хода публикуются как верхняя граница.
- **Версия Chrome** — предустановленный Chrome образа `ubuntu-24.04`. Версия меняется вместе с образом и всегда записывается.
- **Действия** `actions/checkout@v4`, `actions/setup-node@v4`, `actions/upload-artifact@v4` закреплены по тегам, как в `alpha-ci.yml`. Закрепление по SHA не проверено: GitHub API этих репозиториев из среды Builder недоступен.

## Локальное воспроизведение
```
node scripts/check-inspector-browser.cjs --mode=local
# строгий режим (нужны root для подготовки и обычный пользователь для запуска):
sudo unshare --net -- runuser -u <user> -- env -i PATH=<node>:/usr/bin:/bin HOME=<tmp> TMPDIR=<tmp> \
  node <read-only tool>/scripts/inspector-browser-measure.cjs --target=<read-only checkout> --expect-sha=<SHA> --isolation=strict
```
Нужны Node 22+ и Chrome/Chromium. Сторонних пакетов нет.
