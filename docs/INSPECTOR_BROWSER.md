# Независимый браузерный замер Inspector (GIFTED-INSPECTOR-CI, #51)

Утверждено PO 26.11.2026 (Issue #51). Инструмент для **независимого Inspector**. Inspector сам запускает замер и сам оценивает результат. Builder не выдаёт вердикт и не подменяет запуск Inspector своим тестом.

Это **не обязательный статус CI** и не часть `alpha-regression`. Защита веток и полномочия не меняются.

## Что измеряется
Методика #46 (та же, что `scripts/measure-tactician-browser.py`):
- время каждого решения стратегии (по умолчанию `strategist`) против Новичка;
- headless Chrome с замедлением CPU через CDP (`Emulation.setCPUThrottlingRate`), по умолчанию 1×, 4×, 6×;
- `games` партий на каждую скорость (по умолчанию 60): места p/e чередуются, герои по кругу eng/ast/kee, партия g использует LCG-seed g+11, по 6 решений за партию.

Для каждой скорости отдельно по сторонам p, e и вместе:
- число решений;
- среднее, p50, p95, p99, максимум (перцентиль — ближайший ранг, floor);
- число решений дольше 1 с.

Это эмуляция на CPU раннера, а не измерение смартфона. Реальное устройство — задача 004D.

## Запуск (Inspector)
Workflow `.github/workflows/inspector-browser.yml`, событие `workflow_dispatch`.

- **Интерфейс:** Actions → «Inspector browser measurement» → Run workflow.
  - Branch: **main**.
  - `sha` — полный SHA проверяемого коммита.
  - Остальные параметры по умолчанию.
- **CLI:**
  ```
  gh workflow run inspector-browser.yml --ref main -f sha=<40-символьный SHA> -f strategy=strategist -f games=60 -f rates=1,4,6
  gh run list --workflow=inspector-browser.yml --limit 1
  gh run download <run-id>
  ```

Запуск требует права write на репозиторий (у владельца есть). Workflow доступен только после появления файла в `main`.

## Порядок выполнения
1. **Проверка запуска.** Ветка запуска — строго `refs/heads/main`, иначе неуспех. Входные параметры проверяются по строгим шаблонам до любого checkout:
   - SHA — 40 hex в нижнем регистре;
   - стратегия — идентификатор;
   - числа — только цифры.
2. **Checkout измерителя** из `main` на коммите запуска (`github.sha`) в `tool/`.
3. **Checkout проверяемого коммита** в `target/`, `fetch-depth: 1`.
4. **Запись среды:** Node, версия Chrome, образ раннера, CPU.
5. **Самопроверка измерителя** (`check-inspector-browser.cjs`) только на доверенном коде `main` во временных репозиториях. Сценарии:
   - положительный запуск;
   - неверный SHA и сокращённый SHA;
   - отсутствующий браузер и браузер, который не стартует;
   - стратегия не зарегистрирована;
   - недостающие замеры;
   - ошибка страницы;
   - превышение времени;
   - изменённый checkout;
   - блокировка сети.

   Если самопроверка не прошла, замер не выполняется.
6. **Замер** `scripts/inspector-browser-measure.cjs`:
   - сверка `git rev-parse HEAD` с заданным SHA и отсутствие локальных изменений;
   - SHA-256 `game.js` и `tutorial.js`;
   - запуск Chrome и замеры.
7. **Публикация.** Сводка в Summary запуска. Артефакт `inspector-browser-<sha>-run<id>-<attempt>` хранится 90 дней:
   - `measurement.json` — метаданные и результаты;
   - `raw-timings.json` — каждое решение: партия, сторона, ход, мс;
   - `summary.md`;
   - при неуспехе — `error.json`.

## Когда запуск неуспешен
- запуск не из `main` или неверные параметры;
- несовпадение SHA или изменённый checkout проверяемого кода;
- нет файла `game.js` или `tutorial.js`;
- браузер отсутствует, не стартует или не открывает DevTools за 30 с; ошибка CDP;
- стратегия не зарегистрирована в проверяемом коде;
- ошибка или необработанное исключение на странице;
- замер дольше `--timeout-min` (60 мин на скорость), при общем лимите задания 150 мин;
- число решений не равно `games × 6` или не поровну по сторонам;
- некорректные значения времени;
- провал самопроверки.

Измеритель не выносит оценку: превышение 1 с или p95 не делает запуск неуспешным. Числа оценивает Inspector.

## Фиксация версий
`measurement.json` содержит:
- версию (`inspector-browser-1`), коммит и SHA-256 измерителя;
- проверенный SHA и SHA-256 файлов проверяемого кода;
- версию Chrome, ревизию, V8 и user agent;
- Node, ОС, CPU, память, `ImageOS`/`ImageVersion` раннера, номер запуска, инициатора и ссылку на workflow;
- все параметры методики.

Chrome — предустановленный в образе `ubuntu-24.04` (`/usr/bin/google-chrome`). Его версия меняется вместе с образом и всегда записывается.

## Безопасность
- `permissions: contents: read`. Секреты не используются. Оба checkout с `persist-credentials: false`.
- Событие только `workflow_dispatch`; нет `pull_request_target` и других привилегированных триггеров. Workflow и измеритель всегда берутся из `main`, поэтому недоверенная ветка не может их подменить.
- **Проверяемый код никогда не исполняется в Node.** Измеритель читает его как текст и выполняет только внутри страницы `about:blank` headless Chrome:
  - сеть отключена через `Network.emulateNetworkConditions offline`;
  - имена хостов не разрешаются (`--host-resolver-rules`);
  - временный профиль.

  Самопроверка подтверждает, что страница офлайн, а локальный сервер не получает запросов.
- `--no-sandbox`: песочнице Chrome на раннерах часто недоступны user namespaces. Риск ограничен: эфемерная VM без секретов, страница офлайн, токен только на чтение и не сохраняется.
- Действия `actions/checkout@v4`, `actions/setup-node@v4`, `actions/upload-artifact@v4` — по тегам, как в `alpha-ci.yml`. Закрепление по SHA не проверено в среде Builder: GitHub API для этих репозиториев недоступен.

## Локальное воспроизведение
```
node scripts/check-inspector-browser.cjs /usr/bin/google-chrome
node scripts/inspector-browser-measure.cjs --target=<checkout проверяемого кода> --expect-sha=<SHA> \
  --chrome=/usr/bin/google-chrome --strategy=strategist --games=60 --rates=1,4,6 --out=out
```
Нужны Node 22+ (встроенный WebSocket) и Chrome/Chromium. Сторонних пакетов нет.
