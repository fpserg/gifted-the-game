# GIFTED — Политика публикации Alpha
Вступает в силу после независимой проверки и включения PR #33 в main. Product Owner 24.11.2026 утвердил отказ от обязательного GitHub approval второго аккаунта и сообщил об изменении настройки. Это не отменяет независимую инспекцию.
- Все изменения через PR; прямой push в main и обход защиты запрещены. Обязательные alpha-regression и разрешение обсуждений сохраняются.
- Claude Code — Builder, не выполняет merge и не одобряет свою работу. ChatGPT Architect ведёт очередь; независимый Inspector (отдельный процесс, не автор реализации) проверяет фактический diff, требования, тесты и точный HEAD SHA.
- Inspector фиксирует в PR вердикт APPROVE / CHANGES REQUESTED / INSUFFICIENT EVIDENCE, SHA, доказательства, ограничения и findings. Это запись инспекции, не GitHub approval. Новый HEAD требует повторной проверки.
- L0: ограниченные исправления документации, тестов, опечаток и проверенной мелкой косметики; Architect может разрешить публикацию после всех проверок. L1: игровой код, интерфейс, PWA, архитектура — явное разрешение Product Owner на публикацию. L2: правила, баланс, экономика, платежи — отдельное продуктовое решение до реализации и разрешение на публикацию. Защищённая инфраструктура и документы полномочий требуют отдельного разрешения владельца.
- Merge выполняет Architect или Product Owner только после независимого APPROVE на текущий SHA, зелёных обязательных проверок, отсутствия существенных нерешённых замечаний и конфликтов, соответствующего разрешения и соблюдения защиты GitHub. При отсутствии доказательств — BLOCKED. Никакого автоматического merge или активации событий.
- Независимая инспекция теперь процессуальная, не технически обязательная проверка GitHub. Не выдавать комментарий за формальное approval. При серьёзной регрессии остановить публикации и подготовить revert PR.
- PR #32 и прежние предложения автоматического approval не активируются; не сливать их в прежнем виде. Перед денежными наградами пересмотреть модель безопасности.

## Дополнительные обязательные ограничения
- Inspector не изменяет проверяемый PR и не выполняет его merge. Каждое замечание содержит важность (BLOCKER/MAJOR/MINOR), файл, доказательство и предлагаемое исправление.
- PR-workflow используют только права чтения репозитория и не получают секреты; запрещён запуск недоверенного PR-кода с привилегиями. Новая обязательная проверка вводится только после подтверждённого успешного запуска на main.
- CSS относится к L0 только при локальной косметической правке без изменения поведения, навигации, компоновки, доступности, safe-area или PWA, с подтверждённым визуальным результатом. Иначе L1 или выше по фактическому риску; при сомнении L1.
